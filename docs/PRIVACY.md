# Privacy and network behavior

Loqui is a local-first desktop application. It has no hosted Loqui account, analytics upload, remote backup, or synchronization service. Local processing and remote provider processing are separate choices; choosing a local model does not make every optional feature offline.

## Content and retention

Notes, folders, conversations, meetings, dictionary entries, snippets, and transcription history are stored in the local workspace. Audio and downloaded models also use local files.

With Labs → The Table on, card positions, links and each Space’s canvas viewport are stored in the local SQLite database. These layout records contain no note text. Removing a card returns it to the bounded recent Inbox tray without deleting the underlying note, dictation or conversation; older content remains available through History and List. The per-Space List/Table preference is stored separately in localStorage. The browser preview keeps sample layout only in memory until reload.

Chat history also stores, on this device, the titles of the notes an answer used and a short excerpt (up to 240 characters) of each, so the Sources row can be shown later. This local storage feature adds no new transfer; when remote inference is selected, that provider already receives the context supplied to the request.

On a fresh profile:

- Local transcription history is enabled.
- Transcripts have no automatic expiry (`transcriptRetentionDays = 0`).
- Retained dictation audio expires after 30 days.
- Discarded transcriptions are not saved by default.

Change retention in **Privacy & Data**, or turn off local history during onboarding. Retention controls are not a blanket deletion policy for notes, conversations, meetings, exports, or backups. Changing a preference should not be treated as proof that all previously stored content has been erased. The onboarding trial suppresses automatic history/audio retention and automatic paste.

When you cancel a dictation, Loqui keeps that recording in memory for 5 seconds (10 seconds for recordings over 30 seconds) so you can undo the cancel. The hold never writes a file, including temporary files, unless you have turned on saving discarded transcriptions. When the window ends, Loqui overwrites its owned mutable audio bytes and releases the recording. Immutable browser Blobs and copies already sent to a provider cannot be overwritten; their references are released. Undo sends the audio along the same route it was recorded for, never to a provider you chose afterwards. Cancelling stops audio still queued for an opening connection. When dispatch evidence exists, Loqui says the provider may have received the audio or text; stronger receipt wording requires main egress evidence. One case predates the cancel: if the main process had already begun combining a recording's parts, or a local engine was already reading it, that step's temporary file is removed when the step finishes, as it would be for any dictation.

The SQLite database, recordings, and exports are not encrypted by Loqui. Protect the computer, OS account, and backups accordingly. Logs, screenshots, exports, and diagnostics may contain private content; review and redact them before sharing in a public issue.

- Setup reads your system languages, total memory, free disk space and graphics hardware to recommend a voice model. These values are read on your device, shown to you on the Voice step, and are not stored or sent anywhere.

## Storage and credentials

Product identity is defined in [`src/config/product.json`](../src/config/product.json).

| Data                                    | Default location or service                                                                    |
| --------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Packaged workspace                      | Platform application-data directory plus `io.github.snowopsdev.loqui`                          |
| Development workspace                   | Platform application-data directory plus `io.github.snowopsdev.loqui-development`              |
| Packaged provider credential service    | `io.github.snowopsdev.loqui`                                                                   |
| Development provider credential service | `io.github.snowopsdev.loqui-development`                                                       |
| Model cache                             | `~/.cache/loqui-snowopsdev`, or the corresponding absolute `XDG_CACHE_HOME` directory on Linux |
| Development model cache                 | Same location rule with `loqui-snowopsdev-development`                                         |
| Codex state                             | `codex/` and `codex-workspace/` within the Loqui profile                                       |

Provider credentials saved by the application use the main-process credential store. It uses AES-256-GCM with a key stored in the OS credential service, or Electron's `safeStorage` fallback when necessary. Protection depends on the OS and the available credential backend. Environment variables and manually created configuration files are not made private merely by launching Loqui.

Settings windows never hold a saved credential. They learn only whether a slot is stored, and a key counts as saved only after the main process has written it to the credential store. When you remove a key, it is deleted from the credential store at once and kept only in main-process memory for 8 seconds so **Undo** can restore it; replacing the key, the 8 seconds passing, or resetting the app discards it. Resetting the app first stops every key save, removal and Undo still in progress, and only then deletes the credential store, so none of them can bring a key back. Codex sign-in presence is detected by checking that `auth.json` exists in Loqui's Codex profile; its contents are not read and no Codex process is started.

Codex authentication is separate from provider API keys. Loqui starts `codex app-server` with its own profile and file-based Codex credential storage; it does not copy an existing CLI session. Treat the entire Codex profile as sensitive.

`LOQUI_CACHE_ROOT` explicitly selects another model-cache location. Unpackaged development/test runs can use `LOQUI_PROFILE_DIR` to select a separate profile. These overrides do not migrate another application's data. Beta and stable Loqui releases share the production profile. Loqui does not import, move, or delete OpenWhispr or Whispr Personal data.

Uninstalling the application may leave its profile, model cache, and OS credential entries. Review what you need to retain before deleting any of them; local deletion does not remove independent backups or copies already sent to a provider.

## Sealed mode and the flight recorder

**Sealed mode** (Privacy & Data) is enforced in the main process. The version in this build is partial (Plan 07a), so read its limits before relying on it.

- **What it blocks.** While Sealed mode is on, main refuses the requests that Loqui's own JavaScript and its Chromium pages would send to another computer: cloud speech and text providers, provider checks and key verification, model and runtime downloads, URL imports, update checks, downloads and installs, and calendar sign-in and sync. A refused request is not sent. Work already under way when you turn Sealed mode on is stopped, and Loqui says the provider may have received part of it, never that nothing was sent.
- **What stays allowed.** Only loopback addresses on this computer: `localhost`, `*.localhost`, `127.0.0.0/8`, `::1`, and IPv4-mapped `127.x` addresses such as `::ffff:127.0.0.1`. A host name that merely resolves to a loopback address does not count. A self-hosted server elsewhere on your network is blocked like any remote server. A proxy or port forwarder you run on this computer is outside what Loqui can see or stop: if it relays loopback traffic onward, Sealed mode does not block that.
- **Local engines are not available on this build while Sealed mode is on.** Loqui cannot yet put the programs it starts (the built-in speech and language engines, FFmpeg, Codex, yt-dlp and OS helpers) inside a verified network boundary, so it refuses to start them while sealed instead of running them unconfined. Routes that need them show "Unavailable in Sealed mode on this build". The isolation work that would let them run (Plan 07b: decision D16 for macOS and the D15 conditions for Linux) is still pending; until it passes, Sealed mode is partial protection, and the Plan 07 merge gate stays closed.
- **Outside Sealed mode.** Your browser, mail app, other apps and the operating system. Links and OS settings open in them only after you confirm in a system dialog that the app window cannot answer for you. That holds for a link in any Loqui window, including an Assistant answer and a `mailto:` link; no link opens inside Loqui.
- **Turning it off and failures.** If the setting cannot be read, Loqui starts sealed. Turning Sealed mode off asks in a system dialog whose default keeps it on. The panel says what main reports; on this build it always states that Sealed mode is not fully available, and it never describes the seal as verified.

When Sealed mode blocks a request, your content is kept. A chat message stays in the conversation. A dictation recording is kept in History when local history and audio retention allow it; otherwise it is held in memory only, for up to 30 minutes and at most three recordings, with a **Transcribe** action, and it is never written to disk. While sealed, a dictation that would use a cloud speech-to-text route does not start at all.

The **flight recorder** (Privacy & Data, below Sealed mode) lists what Loqui's own network guards recorded: start and end time, task, the bare host names contacted (up to eight, including redirect and CDN hosts), bytes sent and received when measurable, outcome, HTTP status or an error category, and the model id. It never stores audio, text, prompts, keys, full URLs with paths or queries, or error messages. Bytes count request and response bodies, not headers or encryption overhead. Every connection row (live transcription, and connections Loqui saw but could not match to a single request) counts the bytes of the whole connection instead, and the individual requests inside a connection are not visible to Loqui. A count Loqui could not measure shows "—", never zero; only a request that Sealed mode refused before connecting shows as not sent. Codex and yt-dlp run as separate programs that make their own connections: each run appears as one session with its usual host, marked as not visible to Loqui, and their individual requests are not listed. Requests to loopback addresses are not listed. While Sealed mode is on, a local program Loqui refused to start is noted once per program each time Sealed mode is turned on, by program name (such as `pactl`). The panel shows these apart from requests: it counts the distinct programs Sealed mode didn't start today ("Sealed mode didn't start 2 local programs"), so a program refused in two sealings counts once, and names them ("Programs not started: …") from every record of the day, not only the listed ones. A program Loqui could not name is counted but not named. A program that wasn't started isn't a request, so it is never counted as a blocked request or an unexplained host.

The panel shows what was recorded today: every request that ran at any point since local midnight, so one that started before midnight and finished today is listed and counted today. It lists them newest first, 500 records at a time and up to 5,000; export the CSV to see the rest. When the list is cut, the timeline is marked partial, because it draws only the listed records. Records follow transcript retention: with a retention period they are deleted after it, and with "Forever" the newest 100,000 are kept. Turning local history off affects new records only. New records are kept in memory only (the newest 500) and disappear when Loqui quits; records made while history was off are never written to disk later. Records saved before you turned local history off stay on this computer, and stay listed, until retention deletes them or you clear them. **Export CSV** saves every stored record to a file you choose. **Clear history** deletes them all from this computer after you confirm in a system dialog. If a record could not be saved, the panel says the flight recorder couldn't save some records, so the list may be incomplete. If records could not be deleted (a failed Clear or retention cleanup), it says so instead: older entries may still be stored. If the records could not be read while an earlier list is still shown, it says that list may be out of date. In each case the list, Export and Clear stay available; only a failure to read the records when the panel loads hides the list. Like the rest of the SQLite database, the stored records are not encrypted by Loqui.

The recorder is a log of what Loqui observed, not proof about what left this computer: records can be cleared or pruned, memory-only records vanish when Loqui quits, and traffic from other programs (your browser, a forwarder, or a program you started yourself) is not recorded. An empty list means no records, not no traffic.

## Updates and calendars

Automatic update checks and downloads are enabled by default after onboarding. Checks run when due at startup and approximately daily; failures use bounded retry delays. Disable automatic updates in **System** settings. No GitHub credential is embedded in the application. Installation requires **Restart to Update** and is blocked while relevant work or saving is active. With automatic updates off, **Check for Updates** still works: it contacts GitHub only when you click it, never downloads, and links to the release instead. While Sealed mode is on, checks, downloads and installs are paused. If Loqui refused an update request, it says nothing was sent; if sealing stopped one already under way, it says GitHub may have received part of it. The message clears when you turn Sealed mode off.

Optional Google and Microsoft connections require independently configured OAuth applications. OAuth completion uses a local loopback page; it does not redirect through OpenWhispr. Apple Calendar uses local OS permissions. Connecting a calendar can schedule background synchronization while the connection remains configured; disconnect it to stop that integration.

The [network inventory](network-allowlist.md) explains why these destinations are not a single fixed firewall allowlist. The [security policy](../SECURITY.md) covers private reporting.
