## 2. Interfaces added beyond INTERFACES.md

Exports from `src/lib/routeGraph.ts`:
- `export const PAYLOAD_PARTS: readonly PayloadPart[]`: the 16 ids, so Task 3 can assert that every part has a locale string.
- `export const TEXT_PROVIDER_IDS: readonly string[]`: personalInference.js PROVIDERS minus `lan`/`local`. It is pinned by a source-guard test.
- `export function routeCredentialId(id: RouteId, providerId: string | null | undefined): CredentialId | null`: the single credential-identity rule. T2, T6, T11 and T12 should use it for keyring dependent-task attribution and blockers, not re-derive it.
- `export function isValidTextEndpoint(url: string | null | undefined): boolean`: T9's endpoint fields can reuse it.

Snapshot conventions, which INTERFACES left implicit and T3's builder must follow:
- `installed` sets hold raw model ids.
- `models` keys are `whisper:` / `sherpa:` / `llm:` / `cloud:<provider>:<model>`.
- `providerHosts` values are bare `host[:port]`.

Fixtures (`test/lib/routeFixtures.js`, CommonJS):
- `makeSnapshot(overrides?: DeepPartial<RouteSettingsSnapshot>): RouteSettingsSnapshot`. Plain objects deep-merge; Set, Map, array, function and null values replace.
- `makeRoute(overrides?: Partial<ResolvedRoute>): ResolvedRoute`. `kind` and `settingsPath` follow `id`.

Rule refinements to the INTERFACES "Resolver rules". These are deliberate; please confirm:
1. **Embedded credentials.** Text endpoints with embedded credentials (`https://user:pw@host`) are `needsUrl`, because main refuses them (personalInference.js:155-156).
2. **Code-less executor errors.** `resolveTranscriptionRoute` errors without a code map to `needsUrl`. These are the self-hosted URL invalid / not configured errors and the Tinfoil proxy refusal; all three are endpoint errors. Unknown future codes map to `unreachable "unsupported"`.
3. **Unknown key plus missing model.** An off-device text route whose key facts are `unknown` and whose model is unset stays `unknown`, not `needsModel`. The T6 planner treats `needsModel` without a size as allowed, so it must not hide an unconfirmed key.
4. **Unsupported providers and modes.**
   - Enterprise mode accepts only bedrock/azure/vertex.
   - A providers-mode text provider outside TEXT_PROVIDER_IDS, or an unknown mode, is remote and `unreachable "unsupported"` (it fails toward disclosure).
   - Meeting with `provider ""` is `needsKey ""`, matching "noProviderSelected".
5. **Self-hosted meeting.** The state is `unsupported`. Locality comes from the URL: `device` only for a valid loopback URL, otherwise `network`.
6. **assistantVision `webSearch`.** It follows the effective scope: `dictationAgentVision` when the override is on (as PAYLOADS.md says), `dictationAgent` when it is off. With the override off, the request runs on the assistant scope. PAYLOADS.md only covers the override-on case.
7. **`resolveLocality` is not called.** Validation must come before the loopback decision. old/header.md says "do not re-implement resolveLocality". Read it as "use Plan 01's `isLoopbackUrl`"; the outcome is identical on every valid URL.
8. **Plain-HTTP `*.localhost` changes from v1.** `http://lmstudio.localhost/v1` is now `needsUrl`; v1 asserted `device`. `isPrivateHost` (urlUtils.ts:20-48) has no `.localhost` rule, so main and the STT executor refuse plain HTTP to it. `https://lmstudio.localhost/v1` stays `device`.
9. **Speech model display.** It is `cloudModel || null`; the executor's implicit default model is not shown. Speech routes with an empty model are still `ready`, as in v1.
