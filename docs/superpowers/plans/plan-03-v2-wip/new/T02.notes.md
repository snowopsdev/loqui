# T02 notes — Credential authority in main

## 1. Findings closed

- **I3** — Secret setters become `saveSecret(storeKey, value)`: the raw value goes only to `credentials.save`; the store field flips to `"__stored__"`/`""` only after main's ack, and a stale ack never overwrites a newer save (sequence guard). `flushSecretSaves()` exported for Apply/Verify. Main persists before acknowledging (new awaitable `EnvironmentManager.persistSecret`; today `_saveKey` returns `{success:true}` before the encrypted write and only logs failures, environment.js:249-264). Main broadcasts `credentials-changed` after save/remove/undo/reset/refresh; `subscribeCredentialChanges()` (called from `initializeSettings`) mirrors per-field presence into sentinels in every window. `ApiKeyInput` keeps the editor open while saving, clears the draft only on success and shows `role="alert"` otherwise. All 25 legacy secret save channels (BYOK loop, Corti pair, two legacy custom keys, Bedrock/Azure/Vertex) answer `{ success, error? }`. `migrateScopeCustomKeys` no longer writes legacy plaintext into zustand. Tests: deferred slow save, failed save (resolve and reject), replacement ordering in main and in the renderer, flush, IPC ack mapping, mounted ApiKeyInput failure/success.
- **I4 (main side)** — `remove(id)` deletes from the store, keeps the values in a main-memory entry with a purge timer (8 s), returns an opaque random token bound to the post-removal generation; `undoRemove` refuses on expiry, purge, replacement (generation moved) and after `reset()` (called from `cleanup-app`). Tests cover restore within window, expiry, purge, replacement, reset, double use, unknown token, and that no result/broadcast contains secret material.

The authority module never requires codexAppServer/codexCli/child_process/fetch. Test traps `CodexAppServer.prototype.start/status/request`, `fetch`, `spawn`, `execFile` and a fake fs whose `readFileSync` throws.
- **I10 (credential half)** — Distinct identities `corti:text` (`CORTI_API_KEY`) and `corti:speech` (client id + secret; present only when both stored). Store mapping and IPC mapping tested.
- Enterprise presence mirrors `personal-inference:credential-status` (bedrock: profile || access key id; vertex: key || project; azure: key). `save-bedrock-profile` / `save-vertex-project` call `credentials.refresh()` so presence events follow non-secret inputs.

## 2. Interfaces added beyond INTERFACES.md

- `createCredentialAuthority` deps: `{ env, codexHome, fs, broadcast, now, undoMs, setTimer, randomToken }`. **`getCredential` dropped**: main.js `getCredential` (main.js:438-441) dispatches to the very same environment getters via `credentialSlot` (main.js:493-506), so the authority reads the getters directly (one read path). Enterprise presence still matches main.js/personalInference semantics.
- Extra authority methods: `present(id): boolean`, `refresh(id): void`, `subscribe(listener) → unsubscribe` (listener gets the change plus `cause: "save"|"remove"|"undo"|"reset"|"refresh"`). Task 11 consumes `present`, `generation`, `subscribe`.
- Exported helpers: `CREDENTIAL_IDS`, `UNDO_MS`, `byokSlotId(base)`, `slotForCredentialRef(ref)`, `hasStoredAccount({fs, codexHome})`.
- Slot ids beyond `CredentialId`: `custom:transcription`, `custom:dictationCleanup`, `custom:noteFormatting`, `custom:dictationTranslation`, `custom:dictationAgent`, `custom:dictationAgentVision`, `custom:chatIntelligence` (named like personal-inference credential refs). `list()` returns only the 16 `CredentialId`s; events fire for all slots. Type `CredentialSlotId = CredentialId | \`custom:${string}\``.
- `fields: Partial<Record<CredentialField, boolean>>` added to both `list()` entries and the `credentials-changed` payload. Needed because the store has per-field sentinels (`cortiClientId`/`cortiClientSecret`, three Bedrock fields) while presence is per identity (corti:speech needs both).
- `CredentialField = "key" | "clientId" | "clientSecret" | "accessKeyId" | "secretAccessKey" | "sessionToken"`.
- Error codes: `CredentialError = "unknownCredential" | "unknownField" | "invalidValue" | "persistFailed" | "unsupported" | "notStored"`. `undoRemove` failure reason gains `"persistFailed"` (write failed while restoring; values kept for a retry inside the window).
- `EnvironmentManager.persistSecret(envVarName, value): Promise<void>` (awaitable; rejects and restores on failure; rewrites `.env` when OS encryption is unavailable).
- `IPCHandlers._acknowledgedSave(id, field, value) → { success, error? }`.
- Renderer: `SecretStoreKey`, `SecretSaveResult { ok; error? }`, `subscribeCredentialChanges()`; `saveSecret` is an exported module function (setters delegate to it). `invalidateApiKeyCaches(provider, { persistEnv })` gains an options arg (acked saves no longer trigger the renderer's debounced `.env` rewrite; main already persisted).
- Types: `SecretSaveAck`, `CredentialsAPI`, `CredentialPresence`, `CredentialChange`, `CredentialSaveResult`, `CredentialRemoveResult`, `CredentialUndoResult` in `src/types/electron.ts`; `credentials` declared required on `electronAPI` (preview stub added).
- Test harness `test/helpers/harness/fakeCredentialEnv.js` (`fakeCredentialEnv`, `fakeCodexFs`) shared with Task 11.
- Scope split: INTERFACES' "Renderer (T2)" paragraph also lists `ApiKeyInput credentialId` + inline "Removed · Undo".
