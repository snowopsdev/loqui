### Task 5: Route chips, an honest mode selector and contrast (SET-Q4)

Closes I13 for the mode selector, the chips and the cloud model list (contrast measured with opacity compositing over the real Settings surfaces, in both themes, and the light focus ring token), and M1 for the mode selector (focus and selection are exercised through handler props, not only SSR role counts). It also adds the `unknown` ("Checking…") chip state and the `retired` and `unsupported` details that the v2 route graph introduces.

"Active" means "mode selected", not "usable" (SET-04). This task does four things:
- It replaces "Active" with "Current" plus the route's real state chip, including the three new cases: `unknown` reads "Checking…", and `unreachable` has the details `sealed`, `retired` and `unsupported`.
- It makes the mode selector a real radio group: `role="radiogroup"`/`radio`, `aria-checked`, a roving tab stop, arrow keys that move focus (Enter and Space choose, because choosing a mode changes a route).
- It ships the two chip primitives every later screen uses.
- It fixes the contrast of everything it touches and pins the Settings surfaces with composited tests in both themes (Plum Night extension included).

Design decisions worth reviewing:
- **Arrows move focus; Enter or Space choose.** A radio group normally selects on arrow keys, but here a selection is a route change: instant with an Undo toast on device, a staged draft otherwise (Tasks 7 and 8). Arrowing through Cloud on the way to Local would stage and then replace drafts. The model cartridge grid (Task 13) follows the same rule.
- **Chip words never use `text-destructive`.** It is 4.43:1 on the muted, secondary and surface-3 fills (`#dc2626` on `#f5f5f5`). Chip text is foreground, muted-foreground or the device role; the destructive hue is carried by the glyph (a non-text mark, 3:1 minimum, measured 4.06:1 at worst).
- **The selected mark is the ring token, not solid `primary`.** Solid `#ff5a1f` is 2.94:1 on a hovered row. The ring token (`#E84E16` light) is 3.19:1 or better on every Settings surface, and orange stays within the D1 allowance (focus ring, selected-card border, active-nav marker).
- **Descriptions are full-strength `text-muted-foreground`.** At `/80` it is 4.46:1 on a hovered row in light.

function walk(node, visit) {

async function surfaces(tokens, theme) {
  const { parseHexColor } = await load();
  const hex = ({ r, g, b }) =>
    "#" + [r, g, b].map((v) => Math.round(v).toString(16).padStart(2, "0")).join("");
  const over = (fg, alpha, bg) => {
    const f = parseHexColor(fg);
    const b = parseHexColor(bg);
    return hex({
      r: f.r * alpha + b.r * (1 - alpha),
      g: f.g * alpha + b.g * (1 - alpha),
      b: f.b * alpha + b.b * (1 - alpha),
    });
  };
  const dark = theme === "dark";
  const pane = dark ? tokens["--color-surface-1"] : tokens["--color-background"];
  const panel = dark ? over(tokens["--color-surface-2"], 0.5, pane) : over(tokens["--color-card"], 0.5, pane);
  const hoverRow = dark ? over("#ffffff", 0.03, panel) : over(tokens["--color-foreground"], 0.03, panel);
  const tile = over(tokens["--color-primary"], dark ? 0.15 : 0.1, hoverRow);

   ```ts
   // Roving-tabindex arrow handling for radio groups and option grids.
   // Pure, so keyboard behaviour is testable without a DOM.

   export type NavKey = "ArrowUp" | "ArrowDown" | "ArrowLeft" | "ArrowRight" | "Home" | "End";

   // A vertical list moves with Up/Down; Left/Right are the secondary pair and
   // swap in right-to-left layouts. Returns `index` unchanged for any other key.
   export function stepLinear(
     index: number,
     key: string,
     disabled: readonly boolean[],
     rtl = false
   ): number {
     const n = disabled.length;
     if (n === 0 || disabled.every(Boolean)) return index;
     const scan = (from: number, dir: 1 | -1) => {
       let i = from;
       for (let step = 0; step < n; step++) {
         i = (i + dir + n) % n;
         if (!disabled[i]) return i;
       }
       return index;
     };
     const next = rtl ? "ArrowLeft" : "ArrowRight";
     const previous = rtl ? "ArrowRight" : "ArrowLeft";
     switch (key) {
       case "ArrowDown":
       case next:
         return scan(index, 1);
       case "ArrowUp":
       case previous:
         return scan(index, -1);
       case "Home":
         return scan(n - 1, 1);
       case "End":
         return scan(0, -1);
       default:
         return index;
     }
   }
   ```

   Up and Down always move; Left and Right are the secondary pair and swap when `rtl` is true. Task 13 adds `stepGrid` to this file.
