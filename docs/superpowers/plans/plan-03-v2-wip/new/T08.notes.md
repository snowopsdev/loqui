# T08 notes — Stage, review, apply in the editors

## 1. Findings closed

- **I1 (editor half).** All four mode selectors (SettingsPage `TranscriptionSection` :526-548, MeetingSettings :87-95, UploadSettings :68-75, InferenceConfigEditor :99-122) call `request(routeId, stagedTargetForMode(...))`, which goes to `requestRouteChange`. The planner decides instant or staged, so a loopback self-hosted or custom target applies at once. Re-picking the active mode discards that route's draft. Tests: `routeModeEditors.test.js` (mounted Meeting, Upload and Chat; source guard for the non-exported TranscriptionSection) and `stagedRoutePanel.test.js` ("Use this server" on loopback → instant, remote → staged).
- **I6 (display).** `StagedRouteBarView` renders every `plan.changes` entry (`data-route`), marks `coupled` ones "Also changes", and shows each route's destination chip, `host` and `sends`. Under the list it adds the PAYLOADS.md footnote `routes.payload.metadataNote`. The bar renders Task 7's `planDraft`, the same plan `applyDraft` re-runs at click time.
- **I7 (bar).** The host shown is `change.after.host` (the resolver's effective host), never a target re-read.
- **I10 (UI).** `credentialFor(routeId, "corti")` returns `corti:speech` with `cortiClientId` and `cortiClientSecret` for speech routes, and `corti:text` with `cortiApiKey` for text routes. The staged panel renders exactly those fields. Tested pure, in SSR and mounted.
- **I3 (editors).** Staged-panel key fields save through Task 2's exported `saveSecret(storeKey, value)`, which awaits main's `credentials.save` acknowledgement. `hasSavedCredential` reads only the store sentinels that main has acknowledged. Apply goes through Task 7's `applyDraft`, which awaits `flushSecretSaves`. The mounted test asserts that main received `["corti:speech", "clientId"]` and that the store holds only `"__stored__"`.
- **I14 (UI).** The bar subscribes through `useSealedStore` and plans with Task 7's `planDraft`, whose `currentPlanContext` uses `getSealed()`. It never reads `routeFactsStore` for sealed state.
- **SET-Q10.** `useRouteChange` toasts Task 7's `routeChangeMessage(plan, t, copy.list)` (task, destination, payload, coupled routes) with a `routes.toast.undo` action. An undo that Task 7 stages shows `routes.toast.undoStaged` and waits in the bar. The old "On Device"/"Cloud Providers" toasts and `CLEANUP_MODE_TOAST_KEY` are removed.
- **providersForRoute per context.** Meeting uses `getMeetingStreamingTranscriptionProviders()` ∩ `MEETING_STREAMING_PROVIDER_IDS` with no custom endpoint. Upload drops `STREAMING_ONLY_PROVIDERS`. Text and vision use the provider registry's `textGeneration`/`images` capabilities.
- **⌘↵ only inside Settings.** The keydown handler requires `event.target.closest("[data-settings-dialog]")`; SidebarModal's Content carries that attribute. Mounted test fires outside (no apply) and inside (applies).
- **Closing the modal discards the draft.** SettingsModal passes `withDraftDiscard(onOpenChange)`. A mounted test calls the dialog element's `onOpenChange(true/false)`, and the bar also discards on unmount.
