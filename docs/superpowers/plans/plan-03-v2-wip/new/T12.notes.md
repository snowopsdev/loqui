# Task 12 notes

## 1. Findings closed

- **I4 (UI half).** `ApiKeyInput` takes `credentialId?: CredentialId`. With it, Remove calls `window.electronAPI.credentials.remove(id)` and shows an inline "Removed · Undo" (a persistent `role="status"` region) for at most 8 s (`UNDO_WINDOW_MS`, clamped to the `expiresAt` main returns); Undo calls `credentials.undoRemove(token)`. The token is held only in hook state and never rendered. Mounted tests with a fake credentials api: undo within the window; after expiry (main answers `expired`, plus a hook-level test of the 8 s timer with an injected clock); after replacement (main answers `replaced`, and saving a new key in the same field drops the pending Undo). They also assert the secret setter is never called on the credentialId path, no call argument contains the stored value, a refused removal keeps the key and says why, and the plain `setApiKey("")` path is kept without a credentialId or without the credentials api. Remove waits for the field's own pending save so a late save cannot resurrect the key.
- **I11 (UI half).** `useKeyringController` awaits `flushSecretSaves()` before every Verify (including each step of Verify all). Row content comes only from `keyring.list()`, refreshed after each Verify, on `keyring.onChanged`, and after a reminder change; the latest list request wins; a failed refresh keeps the previous rows and flags the error. A verdict that main marks `superseded` shows "The key changed while it was being checked"; a stale verdict without the flag still cannot overwrite the listed row (both tested). Verify all is sequential, refuses to start a second run, skips credentials removed meanwhile, and stops when sealed mode turns on between requests. Nothing verifies on mount, refresh or change.
- **I10.** Rows are per credential identity; `corti:text` and `corti:speech` get distinct labels (`keyring.identity.cortiText/cortiSpeech`), distinct reminder-switch names, and distinct paused-task attribution (`pausedTasksByCredential` uses `credentialIdFor(providerId, route.kind)`).
- **I13.** `STATUS_DOT`: verified `bg-locality-device`, unverified and unreachable `bg-locality-remote`, rejected `bg-destructive`; a source guard bans `bg-warning`, `text-warning`, `text-success` and the grey surfaces (`bg-muted`, `bg-secondary`, `bg-surface-3`) in the panel; a token test measures dots at >= 3:1 and destructive text at >= 4.5:1 on background and card in both themes. `ApiKeyInput` errors use foreground text with a destructive dot, not destructive text.
- **Rule 1.** Verify's tooltip and accessible name name the credential and the receiving host ("Sends the saved credential 'Groq' to api.groq.com to check it."); Verify all's tooltip says each credential goes to its own provider, one at a time.
- **I14 (Keyring part).** Sealed state via `useSealedStore` for the buttons and `getSealed()` at click time and between Verify-all steps.
- **M5.** Every test labelled; mounted tests use the personalWorkspace pattern; i18n via `withI18nMock`.
