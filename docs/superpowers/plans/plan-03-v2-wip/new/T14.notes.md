## 2. Interfaces added beyond INTERFACES.md

- IPC args: `storage-delete-audio(expected: { files: number })` and `storage-delete-history(expected: { total: number; files: number })`. The reviewed counts are sent so main can refuse with `"stale"`. A missing or malformed `expected` gives `"invalid-request"`. Inside main, `expected === undefined` means unchecked, and only `cleanup-app` uses that.
- `StorageHistoryDeleteResult extends StorageDeleteResult { audio: { deleted: number; remaining: number | null } }`. The history result needs both counts because the confirmation names both.
- `createStorageOps({ audio, database, broadcast })` → `{ preview, deleteAudio({ expected?, reconcileFlags? }), deleteHistory({ expected? }) }`; exports `isStoredAudioFile`, `HISTORY_COUNT_SQL`.
- `AudioStorageManager.measure(): { files: string[]; bytes: number; directory: string }` (throws); `AudioStorageManager.removeFiles(names: string[]): { deleted: number; failed: { file: string; error: string }[] }` (never throws).
- Exported types in `src/types/electron.ts`: `StorageAudioPreview`, `StorageHistoryPreview`, `StoragePreview`, `StorageDeleteResult`, `StorageHistoryDeleteResult`; optional `window.electronAPI.storage`.
- Renderer-only `DeleteOutcome` widens `deleted` to `number | null` (null = main's answer unknown, e.g. rejected IPC).
- `errors` strings use stable prefixes: `stale`, `invalid-request`, `count-failed:`, `delete-failed: <file>:`, `recount-failed:`, `flags-failed:`, `history-failed:`, plus renderer-side `ipc-failed:`, `invalid-result`, `reset-failed:`.
- `storage-delete-audio` reconciles `has_audio` only for rows whose recording is provably gone (ids parsed from `-<id>.webm`). The old `delete-all-audio` cleared every flag even after partial failures.
